# Aria of Ash

3D 오픈월드 액션 게임 · Unity / C# · 1인 개발

원신 스타일의 3D 오픈월드 액션을 참고해 제작 중인 개인 포트폴리오 프로젝트입니다. 궁극기 연출·카메라 워크 같은 전투 연출과, 오픈월드 환경에서의 렌더링 최적화를 중심으로 개발하고 있습니다.

## 핵심 시스템 1: 전투 연출 (카메라 & 컷씬)

궁극기 사용 시 플레이어 모션과 카메라 구도를 함께 연출하고, 특정 퀘스트 구간에서는 컷씬을 진행시키는 연출 시스템을 직접 구현했습니다. 단순히 기능을 동작시키는 것을 넘어, 그 순간이 플레이어에게 어떻게 체감되는지를 고려해 연출 타이밍과 카메라 구도를 조정했습니다.

## 핵심 시스템 2: 렌더링 최적화 (LOD & Terrain)

배경 오브젝트가 많은 마을 씬에서 LOD Group을 도입했는데, 오히려 성능이 나빠지는 문제를 겪었습니다. 원인을 두 단계에 걸쳐 추적하고 해결한 과정입니다.

| 단계 | FPS | Batches | Tris | SetPass calls |
|---|---|---|---|---|
| LOD 적용 전 | 54.4 | 1968 | 2.1M | 715 |
| LOD Group 적용 직후 (문제 발생) | 48.3 | 2294 | 3.1M | 722 |
| LOD Bias 수정 후 | 62.0 | 1918 | 1.8M | 713 |
| Terrain 렌더링 거리 조정 후 (최종) | **81.0** | **1460** | **1.6M** | **307** |

**원인 추적 과정**
1. 비활성화된 MeshRenderer의 중복 렌더링을 의심했으나, 비활성화된 렌더러는 렌더링 통계에 영향을 주지 않음을 확인하고 배제
2. Quality Settings의 `LOD Bias`가 2.0으로 설정되어 있어, 고해상도 LOD가 실제보다 훨씬 넓은 범위까지 유지되고 있음을 발견 → 기본값 1로 복원 (62.0fps로 회복)
3. 그럼에도 특정 방향(풀·나무가 많은 구간)을 바라볼 때 수치가 급격히 튀는 것을 발견 → 카메라를 회전시키며 방향별로 비교해 원인을 좁힘 → Terrain의 Tree/Detail Object 렌더링 거리가 최대치로 설정되어 있음을 확인 → 시각적 차이가 거의 느껴지지 않는 선까지 Detail Object 100, Tree 250으로 조정

**결과**: 최초 상태 대비 FPS 약 49% 개선, Batches 약 26% 감소, SetPass calls 약 57% 감소

## 배운 점

최적화 기능을 하나 도입했다고 해서 안심하지 말고, 로컬 컴포넌트 설정부터 프로젝트 전역 설정(Quality Settings), 렌더링 파이프라인 전반까지 재검증해야 한다는 것을 배웠습니다. 특히 눈에 보이는 증상 하나를 해결한 뒤에도 "정말 이게 최선인가"를 다시 점검하는 습관이 최적화 작업에서 중요하다는 것을 체감했습니다.
